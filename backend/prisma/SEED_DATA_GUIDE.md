## 📝 详细说明

### 1. 必需数据详解

#### 基础数据菜单（ID: 10-16）
```
基础数据 (ID: 10)
├── 计量单位 (ID: 11)
├── 商品分类 (ID: 12)
├── 品牌管理 (ID: 13)
├── 仓库管理 (ID: 14)
├── 供应商管理 (ID: 15)
└── 客户管理 (ID: 16)
```

**为什么必需：**
- 没有这些菜单，用户无法通过 UI 访问基础数据模块
- 虽然可以直接访问 URL，但不符合正常使用流程

#### 默认仓库（Code: MAIN）
```typescript
{
  name: '主仓库',
  code: 'MAIN',
  isDefault: true,
  isEnabled: true,
}
```

**为什么必需：**
- 采购入库、销售出库都需要指定仓库
- 如果没有仓库，无法完成任何库存操作
- 设置为默认仓库，创建商品时自动关联

### 2. 强烈推荐数据详解

#### 常用计量单位
| 名称 | 编码 | 使用场景 |
|------|------|----------|
| 个 | GE | 单个商品 |
| 件 | JIAN | 服装类 |
| 箱 | XIANG | 批量包装 |
| 千克 | KG | 重量计量 |
| 克 | G | 小重量 |
| 升 | L | 液体体积 |
| 毫升 | ML | 小容量 |
| 米 | M | 长度计量 |

**为什么推荐：**
- 用户无需手动创建常用单位
- 统一单位编码规范
- 提升系统易用性

#### 示例分类结构
```
电子产品 (一级)
├── 手机 (二级)
└── 电脑 (二级)
日用百货 (一级)
```

**为什么推荐：**
- 帮助用户理解多级分类概念
- 提供参考示例，降低上手难度
- 可直接在此基础上修改

## 🚀 使用方法

### 首次初始化（全新数据库）

```bash
cd backend

# 1. 生成 Prisma 客户端
pnpm prisma generate

# 2. 执行数据库迁移
pnpm prisma migrate dev --name init

# 3. 执行数据种子（会自动运行 seed.ts）
pnpm prisma db seed
# 或
pnpm prisma:seed
```

### 重置数据库并重新种子

```bash
cd backend

# 重置数据库（会删除所有数据！）
pnpm prisma migrate reset

# 这将重新执行所有迁移和种子
```

### 仅重新运行种子（不删除数据）

```bash
cd backend

# 直接运行 seed.ts
npx ts-node prisma/seed.ts
```

**注意：** 如果已存在数据，`upsert` 会跳过（不会重复创建）

## ⚠️ 注意事项

1. **菜单 ID 冲突**
   - 现有菜单使用 ID 1-4
   - 新增菜单使用 ID 10-16（避免冲突）
   - 如果手动创建过菜单，可能需要调整 ID

2. **编码唯一性**
   - 仓库编码 MAIN 必须唯一
   - 供应商编码 SUP001 必须唯一
   - 使用 `upsert` 避免重复创建错误

3. **密码安全**
   - 默认管理员密码：`123456`
   - 生产环境必须修改！

## 🔧 自定义 Seed 数据

### 添加更多计量单位

编辑 `seed.ts`，在 `commonUnits` 数组中添加：

```typescript
const commonUnits = [
  // ... 现有单位
  { name: '台', code: 'TAI', sort: 9 },
  { name: '套', code: 'TAO', sort: 10 },
];
```

### 添加更多分类

```typescript
const newCategory = await prisma.category.upsert({
  where: { code: 'FOOD' },
  update: {},
  create: {
    name: '食品饮料',
    code: 'FOOD',
    level: 1,
    sort: 3,
    isEnabled: true,
  },
});
```

### 不创建可选数据

如果不需要示例数据，可以删除以下代码块：
- `// 7. 【可选】常用计量单位`
- `// 8. 【可选】示例商品分类`
- `// 9. 【可选】示例品牌`
- `// 10. 【可选】示例供应商`
